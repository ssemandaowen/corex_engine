# corex-accounts

Account identity and connection credential management.

## Ownership

Owns the `connections` table access and broker-connection credential
lifecycle (persist, read, revoke). Account *identity* (`cx_pap_<ulid>` /
`cx_liv_<ulid>`) is generated by callers using `corex-gateway` conventions;
this package does not generate account IDs.

## Public API (`index.js`)

| Export | Description |
|--------|-------------|
| `connectionsService` (`ConnectionsService`) | Connection credential CRUD; credentials encrypted before save, decrypted after read. Unique constraint on `(account_id, connector_type)`. |
| `CONNECTOR_SCHEMAS` | Per-connector-type credential field schemas. |
| `persistBrokerSettings` | Persists broker settings for a runtime (used by the engine boot path). |

## Allowed dependencies

- `pg` — direct PostgreSQL pool access for the `connections` table.

## Known legacy couplings (aliases it still imports)

- `@core/services/pgStore` (`src/brokerPersistenceService.js`) — engine
  persistence store. **Target of J5** (inject DB instead).
- `@core/services/secretsVault` (`src/connectionsService.js`) — engine
  secret vault for credential encryption. **Target of J5** (inject the
  vault instead).

These two `@core` imports are recorded in
`test/fixtures/boundaryAllowlist.json` (J4 ratchet) and are the reason
this package is not yet self-contained.

## How to run its tests

```bash
cd packages/corex-accounts
npm test
```

Tests use `jest --passWithNoTests --testTimeout=20000` and discover
`test/**/*.test.js`. Path aliases (`@root`, `@core`, `@utils`, `@events`,
`@config`) are resolved via the `moduleNameMapper` in this package's
`package.json`.
